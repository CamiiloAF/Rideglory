# Reglas comunes para agentes de feature (F4–F7)

Lee `CLAUDE.md` (contrato), `docs/plans/refactor-v2-plan.md` (decisiones) y la capa base ya creada: `lib/core/`, `lib/design_system/`, `lib/shared/widgets/states/`. Usa esos componentes antes que Material crudo. Referencia de comportamiento de la v1: `git show main:lib/features/<feature>/...` y `docs/features/<feature>.md` — no copies sin decidir si sobrevive.

**Pencil es obligatorio antes de tocar `presentation/`**: lee cada frame con `mcp__pencil__execute` (`Get(id, {depth: 4, resolveVariables: true})` y `TakeScreenshot([id])`). El `.pen` está encriptado: nunca `Read`/`Grep`. Si Pencil falla dos veces, para y repórtalo. Mapea iconos Lucide → `lucide_icons`.

**Backend**: Supabase local ya corre (`supabase status`), esquema en `supabase/migrations/`, seed con qa1@gmail.com / qa2@gmail.com (`Test123.`). Las claves están en `config/dev.json`. Si necesitas una columna o política nueva, añade una migración nueva en `supabase/migrations/` (nunca edites una existente) y corre `supabase db reset`. Nunca contra un proyecto remoto.

**Estructura**: `lib/features/<feature>/{domain,data,presentation}`. Repositorios devuelven `Either<DomainException, T>`; cubits `@injectable` con `ResultState<T>`, provistos con `BlocProvider`; un widget por archivo; cero métodos que devuelvan `Widget`; cero strings en Dart (todo en `lib/l10n/app_es.arb` con prefijo de feature, luego `flutter gen-l10n`); mensajes de error de red/auth también en el `.arb`. Rutas: crea `lib/features/<feature>/presentation/<feature>_routes.dart` que exponga `List<RouteBase> <feature>Routes` y regístralo con UNA línea en `lib/core/router/app_router.dart`. Estados obligatorios en cada pantalla: contenido, vacío, carga (skeleton), error con reintentar, sin conexión.

**Aislamiento**: trabajas en un worktree propio. Antes de empezar: copia `config/dev.json`, `config/prod.json` y `.env` desde `/Users/cami/Developer/Personal/Rideglory/` (están ignorados por git). Si `build_runner` falla por build hooks de `objective_c`, usa `dart run build_runner build --delete-conflicting-outputs --force-jit`. Solo toca tu feature, el `.arb`, la línea del router, `injection.config.dart` regenerado y `test/features/<feature>/`. No toques `pubspec.yaml` salvo necesidad real (dilo en el informe).

**Cierre**: `dart analyze` limpio, `flutter test` verde (unit de casos de uso y cubits con mocktail/bloc_test, widget tests de las páginas principales en sus estados), `flutter build apk --flavor dev --debug --dart-define-from-file=config/dev.json` compila. Luego **commitea en tu rama del worktree** (excepción explícita a la regla de no commitear): `git add -A && git commit -m "feat(<feature>): ..."`. Informe final ≤ 80 líneas: archivos por capa (conteo), pantallas implementadas con su id de Pencil, resultados de analyze/test/build, migraciones añadidas, decisiones tomadas fuera del plan y pendientes.
